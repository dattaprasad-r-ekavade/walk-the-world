# A7 progress — Three.js r170 to r186

The application manifest and lockfile target Three.js 0.186.0. Four-city
visible-Chrome captures were taken with the same frozen set of 36 public city
cell responses. Compare the [r170 baseline](rehearsal-2026-10-28-a7-r170-matched/)
with the [r186 build](rehearsal-2026-10-28-a7-r186-matched/).

| City | r170 p95 | r186 p95 | Change |
|---|---:|---:|---:|
| Pune | 14.0 ms | 14.0 ms | 0% |
| Edinburgh | 34.9 ms | 34.9 ms | 0% |
| Tokyo | 36.0 ms | 41.6 ms | +15.6% |
| New York | 20.9 ms | 20.8 ms | -0.5% |

The initial matched 300-frame comparison had a noisy Tokyo outlier (+15.6% for
r186). Three new matched 900-frame Tokyo runs per version settled with 9/9
available R2 cells, eight resident cells and the same one failed neighbor in
both versions. Their p95 values were:

| Version | Repetition 1 | Repetition 2 | Repetition 3 | Median |
|---|---:|---:|---:|---:|
| r170 | 16.9 ms | 16.8 ms | 16.9 ms | 16.9 ms |
| r186 | 16.8 ms | 16.9 ms | 16.9 ms | 16.9 ms |

The median p95 difference is 0%, within the plan's 5% gate. All six runs reached
engine ready with the expected heading. No shader compilation errors appeared;
the same geometry-merge warning and local `/api/assets` 501 appeared in both
versions. Visual spot checks showed the same street framing in all four matched
city pairs. The six Tokyo reports are in [the repeated-run evidence](rehearsal-2026-10-28-a7-tokyo-repeats/),
and the earlier longer Edinburgh measurements are in [their repeat reports](rehearsal-2026-10-28-a7-edinburgh-repeats/).

The full suite passed (180 tests across 27 files), and the r186 production build
passed. A7 is complete; B1 is the next roadmap item.
